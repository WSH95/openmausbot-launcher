# Risks

| Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- |
| Token exposure through screenshots or UI capture | observed once | high | Treat an exposed token as compromised: revoke it, keep the replacement only in a 0600 `tokenFile`, do not automate browsers on token-bearing pages, and never place the token in argv or transcripts |
| Codex's default workspace-write sandbox blocks listening sockets and loopback HTTP | certain in the recorded default configuration | medium | Evidenced on real OMB 0.1.56 (M1 review, tier 2): `up` exits 1 with `listen EPERM` and names the sandbox in its hint (finding 24 fixed); `status` exits 1 with a network error naming the URL (finding 26 fixed). Long SSE is blocked before its first frame (2026-09-17, Codex 0.154.0, session `01a0ade0-3bad-7f63-8530-cf3e076a800d`). Prefer the installed skill's opt-in `omb-loopback` profile, which extends `:workspace` and allows only `127.0.0.1` and `localhost`; its local listen/connect and public denial probes pass on 0.154.0. The user must copy and select it. A legacy `sandbox_mode` or `[sandbox_workspace_write]` in any loaded layer overrides the profile, and managed policy may refuse it. Scoped escalation or a reachable remote endpoint is the fallback. A user-started server avoids only the listening restriction; the client still needs permitted network access |
| OpenClaw's exec allowlist does not remove the approval prompt | certain in the recorded configuration | low | Verified 2026-09-16 on OpenClaw 2026.9.4: `approvals allowlist add --agent <agent> <path>` stores a command path with scope "any args", but it matches only the form the agent types, so `node <script>` misses an entry for `<script>`. `--announce` on an empty output delivers nothing (`deliverySuppressionReason: "empty"`), which was the other half of this question. Plan for one approval per command rather than for an allowlist |
| OpenClaw's Codex runtime asks for one approval card per command | certain | medium | Keep `tools.exec.mode` at `ask`; `allowlist` refuses every turn at preflight. Answer each "Codex app-server command approval" with `approvals resolve <id> allow-once` inside its 120 s window, never `allow-always`; an expired card leaves the command sandboxed, where loopback is blocked. `skills.entries.<name>.env` is not applied there, so prefix the command with `env OMB_BIN=… OMB_TOKEN= ` (verified 2026-09-16) |
| DeepSeek Harness runs its shell in its own PID namespace | certain | medium | Verified 2026-09-16 on dsh 0.1.5-rc.1: the server process is invisible, so `doctor --server` reports provider-keys unknown and identity false and `status` exits 3. Use `--remote --url http://127.0.0.1:<port>`, which the driver's own hint already names; loopback HTTP itself is allowed |
| A remote binding that is a URL rather than an identity | was certain before the fix | high | Found on the first Tailscale run, 2026-09-16 (bead `oml-9kp`, fixed in `01901f9`): a state bound to `http://127.0.0.1:8899` refused every `--remote` call that named the tunnel, and adopting the tunnel URL instead broke `task` on the dev box, so remote `watch` and `interrupt` were unreachable. Remote mode now compares environment ids and the shared state stays bound to loopback; local mode still pins the URL. Never `import --adopt` to change the URL of a bound state. Residual, not fixed: an absent or revoked bearer through a tunnel reads as "the server identity could not be verified", because an unauthenticated health answer carries no pid |
| A run stops settling after a sibling run closes (bead `oml-fg8`) | observed once | low | Resolved. Found by the first real parallel run, 2026-09-17: after `report --run t14` closed T14, every `watch --run t15` returned `timeout` with `idle for 0 s, not yet settled`. The cause was not the settlement algorithm: closing T14 unmasked the bots it held, which changed T15's evidence once and correctly refused its stored `attention`, and the four watches that followed asked for 8, 8, 12 and 20 seconds against the 30 s quiet window, so each returned the one evaluation its own window had made. A watch that ends inside the window now reports the idle time it observed and the budget the window needs, and `report` names the watch that settles the run. Never go below `--max-seconds 35`; confirmed on real OpenMausBot 0.1.56 by the V16/V17 check of 2026-09-17 (2 bot turns); evidence in `docs/evidence.md` (2026-09-17, its follow-up and the V16/V17 section) and `docs/validation/2026-09-17-parallel-t14-t15.json` |
| The lead omits the run marker | low | low | `attention` after quiet; the agent reads the closing report |
| OpenMausBot churn (daily releases) | high | medium | Pin 0.1.56 in `compatibility` and `metadata.omb-version`; `references/api.md` carries source lines; routes read from the pinned clone only |
| Lifecycle is Linux-only (`/proc` ancestry and start times) | certain | low | macOS gets `attached` mode; Windows unsupported |
| Long tasks need many `watch` calls under host exec limits | certain | low | Each call rehydrates under a bounded deadline and observes its own quiet window; reserve one extra second for checkpoint contention |
| Numbered names after re-import ("Sudo 2") | medium | low | Ids everywhere; `--adopt` by name must name the team |
| Bot turns on the user's subscriptions | certain | medium | Keep real runs bounded and record their counts; T12, the three leader acknowledgment turns, the review's 6 turns, T13's 9 turns, the v2 host pass's 3 turns, the v2 remote run's 2 turns, the 2026-09-17 parallel run's 34 turns and the 2026-09-17 V16/V17 output check's 2 turns each have separate evidence; the v2 pass stands at 41 of its 50 cap. Native host CLI sessions also consume the user's subscriptions: the v2 pass cost 6 OpenClaw, 3 Hermes and 4 dsh turns on top of the 3 host-pass bot turns, and no host sessions at all for the remote run |
| Mixed old/new launcher installations bypass the SQLite mutex | medium | high | Refuse any legacy lock; stop commands and automations, update every copy, then remove only the legacy path; never unlink lock.sqlite |
| A hung writer holds SQLite indefinitely | low | medium | Bounded waits fail without stealing ownership; identify and stop the writer before retrying |
| Node SQLite remains experimental | certain | low | Node 24 supported; lazy import for writes, stderr warning preserved, state JSON format unchanged |
| Unknown server ownership blocks a replacement | low | medium | Fail closed; verify or stop the recorded process before changing the selected server |
| Startup proof fails after spawning the server | low | medium | Refuse success and include URL, log and spawned PIDs in the error; inspect identity before manual recovery |
| `report --check-042` depends on the native-log parser recognising the lead's engine | low | medium | `nativeCalls` reads Claude-SDK blocks and Codex JSON-RPC `item/*` entries (finding 6 fixed; T13's `--check-042` scored a Codex lead 8/9 from a 1.25 MB `codex.app-server` log). A Grok lead's log shape is still unread and would return `unknown`; an `unknown` check is never a pass |
| An identical `send` in one run is a server-side no-op | low | low | `send` reports `duplicate: true` when the server returns the canonical receipt for an already-used `sendId` (finding 8 fixed); `--again` delivers the same text once more |
| The facts test command lives in the lead's description, which a bot can edit | low | medium | `facts` takes the test and setup commands only from the operator's flags or stored facts, never from the lead's block, and `beadStatus` is bounded (finding 10 fixed). Still set `facts --test` explicitly and read `facts` output before `report` |
| `up --port N` also occupies N+1 for OMB's webhook ingress | certain | low | `up` checks N+1 before spawning, reports `ports`, and explains a `404 Unknown webhook endpoint` as a webhook-port collision (finding 23 fixed). Space concurrent servers two ports apart |
| Saving a provider key (`xaiApiKey`, `opencodeGoApiKey`) restarts the whole provider fleet and interrupts every running turn (`index.ts:12003-12014`, `:7173-7207`) | certain | high | `answer --provide` refuses while any bot on the server is busy or any delegation is queued, re-checked immediately before the write, with no override. The server has no idle-conditional write, so a turn that starts in the milliseconds between the check and the write is still interrupted: save provider keys when the team is idle |
| A credential write's outcome cannot be attributed to that write | low | medium | The server persists the config before it reloads providers, so a timeout or a 5xx can follow a successful save. The driver reads the configured state before and after and reports `verified` only for not-configured → configured, otherwise `unknown` with `answer --resume` and `--provide` as the two choices. Never read a lost answer as "not saved" |
| An agent composes a command that carries the secret | medium | high | The skill, the briefs and the design name only two paths: a user-owned 0600 file through `--secret-stdin <`, or `OMB_SECRET` exported in the user's own shell. `tests/docs.test.mjs` fails on any `OMB_SECRET=` in the skill, the references or `docs/*.md` |
